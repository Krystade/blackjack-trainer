**`src/guided/plan.ts`**
- `PlanInput` gains `currentRung: GuidedRung | 'play' | null` (the ladder's current rung; `null` = every
  rung passed) and, in 1C, `rungsSkipped?: Partial<Record<GuidedRung, boolean>>`.
- New `RUNG_ORDER: readonly GuidedRung[] = ['basic','repair','count','tc','deviations','betramp']` and
  `PRIMARY_SEGMENT: Record<GuidedRung, SegmentId>` = basic: warmup, repair: warmup, count: count,
  tc: truecount, deviations: deviations, betramp: bets.
- New `isReached(def, input)`: true when `currentRung` is null or 'play', or when the lowest-ordered rung
  the segment serves is at or before the current rung. Warm-up (basic, repair) and speed (basic) are
  therefore always reached.
- `isWeak`: unchanged rule plus "a skipped rung is not weak" (1C).
- `planSession`:
  1. Drop unreached segments (before the Drive filter, so Drive still drops bets on its own).
  2. Freed weight = the sum of the BASE weights of the dropped segments. It is added to the current
     rung's primary segment (when that segment is in the plan; a Drive plan whose current rung is
     betramp has no bets segment, so the freed weight is just not added).

  4. Apportion and targets as today.

  - Everything reached: today's line, "One tap, a routine: warm-up, speed, counting, true count,
    deviations, bets. Weak spots get longer."

    {rung label, lower case}." For example: "Warm-up and speed for now, the steps you've reached.
    Running count joins when you pass basic strategy." The rung label comes from a restated
    `GUIDED_RUNG_LABELS`, which keeps plan.ts pure. A unit test holds it to `nextStep.RUNG_LABELS`.

Worked example: a new user (current = basic) on 15 minutes. Only warm-up and speed are reached.

warm-up 11 minutes (90 answers) and speed 4.

## Batch 1B: beginner Play table and "What to check"

### Design: switches are Play-only gates over the profile's finer values

The obvious version flips the existing fields: countCheckEvery to 0, gradeDeviations to false,
betSpreadOn to false. I rejected it because those fields are "My system", and other surfaces read them:
- `store/casinoGameStats.ts:207` runs the casino EV sim with `indices: profile.gradeDeviations`. Turning
  Deviations off in Play would silently re-run Jack's casino figures without indices.
- `ProfileEditor.tsx:671` hides the whole bet ramp editor when `betSpreadOn` is false.
- countCheckEvery 0 would lose his cadence.

So each switch is a gate, layered over the finer value. **Play does a thing only when its gate AND its
finer setting are on.**

| Switch (Play gear) | Gate stored at | Finer value (unchanged home) | Turning the switch ON writes |
|---|---|---|---|
| Count checks | `profile.playChecks.count` | `countCheckEvery`, `countCheckAsk` | gate true; `countCheckEvery` 5 if it was 0 |
| Deviations | `profile.playChecks.deviations` | `gradeDeviations`, index sets | gate true; `gradeDeviations: true` |
| Bet checks | `profile.playChecks.bets` | `betSpreadOn`, `spread`, Wong points | gate true; `betSpreadOn: true` |
| Dealer mistakes | `settings.tableChecks.dealerMistakes` | `dealerMistakesMode` | gate true; mode 'occasional' if it was 'off' |
| Distractions | `settings.tableChecks.distractions` | none (new) | gate true |

Turning a switch OFF writes only the gate (false). The switch shows the EFFECTIVE state, gate && finer
on, so a profile whose editor has count checks at "Off" shows Count checks off.

The three profile gates are held in the sheet's draft and written on close with a new shoe, as
PlaySheet does today (`playOptionsDiffer` gains the effective gates). The two settings gates commit
live, as dealer mistakes does now.

**Absent gate = legacy-derived** (count: `countCheckEvery > 0`; deviations: `gradeDeviations !== false`;
bets: `betSpreadOn`; dealer mistakes: mode !== 'off'; distractions: off). After the migration every
stored profile has explicit gates, and new profiles are created with explicit false gates. So absent only
happens for:
- (a) a backup restored from before this change, which then behaves exactly as it did, and
- (b) e2e specs that seed profiles, which keep working unchanged (see the e2e section).

**Types (`src/store/types.ts`, additive only)**
- `Profile.playChecks?: { count?: boolean; deviations?: boolean; bets?: boolean }`
- `Settings.tableChecks?: { dealerMistakes?: boolean; distractions?: boolean }`
- `Stats.distraction.history[]` row gains `source?: 'play'` (absent = Count drill).

**`src/ui/whatToCheck.ts`** (new, pure; the one place the rules live):
- `playChecksOf(profile)` and `tableChecksOf(settings)` return the gates with legacy derivation.
- `checksShown(profile, settings)` returns the five effective on/off states.
- `checkOnPatch(key, profile|settings)` and `checkOffPatch(key)` return the patches in the table above.
- `effectivePlayFields(profile)` returns `{ countCheckEvery, gradeDeviations, betSpreadOn }` as Play must
  use them.
- `tableMistakesMode(settings, eyesFree)` = gate ? `dealerMistakesModeIn(settings, eyesFree)` : 'off'.
- `distractionsOn(settings, eyesFree)` = gate && !eyesFree.

## ASSUMPTIONS
1. Guided "current rung" means the ladder's current rung (with 1C, after skips). When everything is
   passed, or the current rung is 'play', the plan is today's full six. The freed minutes go to the
   current rung's primary segment: basic and repair go to warm-up (Flashcards on the chart or the due
   and weak cells).
2. Drills "After: X" names the drill of the rung just before the drill's own rung, so the labels read
   as a learning chain. The 'Advanced' note is replaced by these labels rather than kept beside them.
   Rules differences, Variant hands and Side count get no label.
3. What-to-check switches are Play-only gates over the profile's finer values (rationale above), and
   Play acts only when gate AND finer are on. Turning on uses the finer value, or 5 rounds /
   'occasional' when the finer value is off.
4. Profile gates (count, deviations, bets) are new-shoe items held until the sheet closes. Settings gates
   (dealer mistakes, distractions) are live.
5. The migration resets the five gates and bots 0 on every profile once, and changes nothing else
   (playerHands, hot shoe, side bet, losing shoe and dealer pace stay as stored). The marker is
   device-local and not backed up, so restoring an old backup restores the old setup.
6. Play distractions: about 1 per 7 rounds (the drill's 'occasional' cadence over rounds), both kinds
   alternating, never eyes-free. "Count kept" is graded by a running-count check right after the
   distraction, and only when Play count checks are on. With them off, the distraction is shown and its
   sum graded on screen, but no stats row is written.
7. The suggestion lives on Home, one at a time, and is never shown on a no-data Home.
8. Welcome: "I know basic strategy" starts at the count rung, and "I count already" starts at
   deviations (skipping basic, repair, count and tc) with Count checks, Deviations and Bet checks on.
   The welcome is a non-blocking card above Next step.
9. The simple Home keeps the 7-rung list under Next step, plus GuidedCard and "Play a shoe". "GuidedCard
   below LadderCard until basic passes" counts a skipped basic as passed for ordering only.
10. If 1A's guided e2e needs a reached-rung seed that stats make heavy, the onboarding store and ladder
    `skipped` (no UI) move forward from 1C into 1A.
